# 5돌이

최근 5거래일 상한가 종목이 5일선까지 눌렸다가 되돌아오는 구간을 노리는 매매 보조 도구.
구글 시트 「5돌 돌려차기」의 계산을 그대로 옮겨 매일 자동으로 돌린다.

## 원칙

1. **수집** — 당일 상한가 종목을 매일 DB(`data/upper_limit.csv`)에 누적한다.
2. **예측** — 최근 5거래일 상한가 종목의 내일 5일선을 예측해 1차/2차 매수가와 매도가를 정한다.
3. **고정** — 계산값을 그날 기준으로 저장한다. 다음 날 시세가 움직여도 값이 변하지 않으므로,
   시트에서 감시 Dashboard로 수동 복사하던 단계가 필요 없다.

## 매매 규칙 (시트 `3.5돌이매매`, `호가계산`, `2.Analysis` 기준)

| 항목 | 계산 |
| --- | --- |
| 내일 5일선(예측) | (당일종가×2 + 전일종가 + 2일전종가 + 3일전종가) ÷ 5 |
| 1차매수가 | 내일 5일선(예측) × 93.85% |
| 2차매수가 | 1차매수가 × 94.8% |
| 매도가 | 내일 5일선(예측) |
| 호가 보정 | 세 가격 모두 호가단위 올림(CEILING) |
| 이격률 | 종가 ÷ 금일 5일선 − 1 |
| 매수대기 | 전일 1차매수가 터치 & 이격률 10% 미만 → `매수선터치`, 이격률 5% 미만 → `5일선근접`, 10% 미만 → `대기` |
| 제외 | 이미 시세를 준 종목, 단일가 종목 → `config.json`의 `exclude_codes`에 종목코드 추가 |

호가단위는 시트 수식(1천 미만 1 / 5천 미만 5 / 1만 미만 10 / 5만 미만 50 / 그 이상 100)을 따르되,
20만원 이상은 주문이 거부되지 않도록 실제 KRX 단위(500, 1,000)를 쓴다.
`config.json`의 `tick_mode`를 `krx`로 바꾸면 전 구간 실제 KRX 호가단위로 계산한다.

## 구성

```
5돌이/
├─ index.html          감시 Dashboard (data/latest.json 표시)
├─ config.json         비율·감시일수·제외종목
├─ src/rules.py        매매 규칙(순수 계산)
├─ src/naver.py        네이버 금융 수집(상한가 목록, 일별 시세)
├─ src/run_daily.py    일일 배치
├─ tests/              시트 값 대조 테스트
└─ data/
   ├─ upper_limit.csv  상한가 종목 DB (누적)
   ├─ signals.csv      일자별 매매가 이력 (누적)
   ├─ latest.csv       최신 매매가 (한글 헤더)
   └─ latest.json      Dashboard용
```

## 실행

- 자동: GitHub Actions `.github/workflows/odol-daily.yml` — 평일 18:40(KST), 수동 실행도 가능
- 수동: `python 5돌이/src/run_daily.py` (파이썬 표준 라이브러리만 사용)

## 구글 시트 저장

배치가 끝나면 `src/gsheet_sync.py`가 구글 시트 「5dol」에 행을 직접 쌓는다.

| 탭 | 동작 |
| --- | --- |
| 상한가DB | 시트에 없는 날짜의 상한가 종목을 맨 아래에 추가 |
| 매매가이력 | 시트에 없는 날짜의 매매가를 맨 아래에 추가 |
| 매매가 | 최신 기준일 값으로 교체 |

필요한 설정: 저장소 Secret `GSHEET_SA_KEY`(서비스 계정 JSON 키)와 시트를 서비스 계정 이메일에 편집자로 공유.
시트 ID는 `config.json`의 `gsheet_id`. Secret이 없으면 이 단계는 건너뛴다.
